Working with Multiple Clusters in SpaceDeck

One SpaceDeck instance can view and manage several XAP clusters. You don't need a separate SpaceDeck for each cluster. An administrator defines the clusters once in spacedeck.yaml. Users then switch between them from a cluster selector at the top of every screen.

How It Works

  • The cluster whose REST service hosts SpaceDeck is the local cluster. You can give it a display name.

  • Each additional cluster is reached through the local REST service, which forwards SpaceDeck's requests to that cluster's own REST service. The browser never calls a remote cluster directly, so no CORS or extra firewall rules are needed for end users.

  • Remote cluster URLs and credentials stay on the server. The browser receives only each cluster's ID and display name.

Configuring Clusters (Administrators)

  1. Open spacedeck.yaml. SpaceDeck reads it from either of these locations:

    • <XAP_HOME>/config/ui/spacedeck.yaml

    • The path set in the SPACEDECK_CONFIG_PATH environment variable

  2. Under the spacedeck: key, add a name for the local cluster and a list of additional clusters:

    spacedeck:
  config:
    # ... existing settings ...

  clusterName: "London Prod"            # display name of the local cluster (default: "Local")
  clusters:
    - id: ny-dr                          # unique ID, used internally and in URLs
      name: "New York DR"                # name shown in the cluster selector
      url: "http://ny-manager-host:9090" # REST (v3) base URL of that cluster's manager
    - id: emea-wan-lab
      name: "EMEA (WAN lab)"
      url: "http://emea-manager-host:9090"

  3. Restart the REST service (or the XAP manager that hosts it) so it picks up the change.

Field Required Description
clusterName No Display name for the local cluster. Default: Local.
clusters[].id Yes Unique, URL-safe identifier.
clusters[].name Yes Name shown to users.
clusters[].url Yes Base URL of the remote cluster's REST service, without a trailing /api/v3.

Entries missing id or name are skipped and logged as a warning. They don't break the other clusters.

Seeing Which Cluster You Are Viewing

The current cluster's name always appears above the page title.

On Administration screens, the cluster name appears next to the SpaceDeck logo.

Switching Clusters

  1. Click the cluster name above the page title.

  2. Pick a cluster from the list. The local cluster is marked (this cluster).

The page reloads. Every screen now shows the selected cluster's data, and its name appears in the selector.

Your selection lasts for the current browser session. Closing the browser or logging out always returns you to the local cluster.

Notes and Limitations

  • Only clusters defined in spacedeck.yaml can be selected. Users can't add clusters from the UI.

  • If an administrator removes the cluster a user is currently viewing, that user is moved back to the local cluster on the next page load.
